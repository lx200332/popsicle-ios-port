## 一、结论

1. **原本以为要真机的大半东西，本地 OTA 里全都有。** 解包 `payload.bin` 的 odm 分区（3,892,228,096 B EROFS）后，Synaptics 双固件（`synaptics_spi_popsicle_00/01.img` 各 198,892 B）、Goodix GT9615 固件（125,440 B）、两份 thp config、两份 test limits、CS35L43 六套 spk-prot、CS40L26 全套、CAMERA_ICP 全套、evass、三套 zap、97 个 thermal zone、67 份 SSC sensor json、面板 LUT 24 份、四摄 tuning 与 acdb 44 MB 全部落地；PCIe PHY sequence（约 200 对 offset/value）、Synaptics 全部 20 个 DT 参数、Goodix/相机/指纹的 GPIO 与供电也都在 live FDT 里——**这些一条都不用问用户**。
2. **真正卡住的只剩 5 类，且高度集中在「运行时状态」而不是「固件/配置」**：PMIC regulator 与 GCC/DISP/GPU 时钟的**运行时实际值**（DT 只有 `init-mode`/`init-voltage`，不等于 Android 跑起来之后的值）、CPU 两簇的**频率档位与 CPUCV level→freq 映射**（vendor DT 只有 8 处 `opp-hz`，域 1「设任意 level 都停在 8」只能靠真值定）、`/mnt/vendor/persist/audio/crus_calr.bin`（全库唯一确认不存在的固件）、Android 侧**完整 dmesg**（我们只有 512 KB pstore 片段）、以及 4 个模组的 **EEPROM OTP**（每台机器唯一，OTA 不可能有）。
3. **P0 合成一个脚本、14 条命令、产物约 40 MB**，跑完能一次性解掉 regulator/clk/cpufreq/dmesg/crus_calr 五件事；剩下 3 类（BT MAC、指纹 probe 实况、相机 OTP）属 P1，跑同一个脚本的第二段即可。**有一批东西真机也解决不了**：SSC/ADSP 的 Apple 侧服务端、Hexagon 上的 AudioReach/ICP/EVA/modem 固件执行环境、TZ 授权的 PAS、以及 AMFI 信任链——这些不是数据问题。

## 四、必须真机的清单

> 前提：`adb -s 6f17201d` 在线（三星那台是 `98895a465253534359`，别打错）。

### P0 —— 不给就卡住（5 项）

#### P0-1 · PMIC regulator 运行时实际状态

**目的**：iOS 侧要自己建 regulator 树。vendor DT 只有 `qcom,init-mode`（50 处）和 `qcom,init-voltage`（89 处），**不等于 Android 跑起来后的值**，更不知道谁在使能它。`regulator_summary` 一次给出：每个 rail 的名字、电压、mode、enable count、以及全部 consumer 名。
**命令**：
```bash
adb -s 6f17201d shell "su -c 'mount -t debugfs none /sys/kernel/debug 2>/dev/null; cat /sys/kernel/debug/regulator/regulator_summary'" > 10-regulator_summary.txt
adb -s 6f17201d shell "su -c 'cat /sys/kernel/debug/regulator/regulators'" > 11-regulators.txt
```
**怎么读**：`regulator_summary` 每行形如 `pmh0101_l9  1  0  0  normal  3300 mV  0 mA  2  0  2` —— 前段是名字/use_count/open_count/bypass/模式/电压/电流，后段 consumer 列表就是「谁在管它」。重点看 `L4I_E0`(touch iovdd 1.8 V)、`L2F_E0`(goodix 1.2 V)、`L9B`(fp 3.3 V)、`S7F0`(WiFi)、`mmcx`(GPU/DPU)、`cam_vana/vdig/custom1/custom3/bob/bob2/vaf`。
**大小**：约 120–200 KB。

#### P0-2 · GCC / DISP / GPU 时钟树运行时速率

**目的**：BT 的 `qupv3_se5`、WiFi 的 `pcie_0_{core,phy}_clk`、DPU 的 `disp_cc_mdss_*`、相机的 `cam_cc_*` —— DT 只给 `clocks = <&gcc N>`，**N 到具体 branch/RCG 偏移映射不在 DT 里**。`clk_summary` 给出「时钟名 → 当前 Hz → enable count」，配合 §16.3 的 `pandora_btse` 扫描可以互证。
**命令**：
```bash
adb -s 6f17201d shell "su -c 'cat /sys/kernel/debug/clk/clk_summary'" > 12-clk_summary.txt
```
**怎么读**：`clock  enable_cnt  prepare_cnt  protect_cnt  rate  accuracy  phase`。搜 `pcie_0`、`qupv3_se5`、`qupv3_se3`、`qupv3_se2`、`mdss`、`cam_cc`、`gpucc`。有 rate 就说明这一路确实被点起来了。
**大小**：约 300–600 KB（SM8850 时钟多）。

#### P0-3 · CPU 两簇频率档位 + CPUCV level→freq 真值

**目的**：`pandora_cpu.c` 里域1「设任意 level 都停在 8」——**必须拿到 Android 真机上的 level→freq 表才能定**。vendor DT 只有 8 处 `opp-hz`，OSPM 表在 `cpufreq` 驱动里。
**命令**：
```bash

```
**怎么读**：`scaling_available_frequencies` 是**降序 kHz 列表**，域0 应约 28 项（384000…3630000）、域1 约 27 项（768000…4610000）。`time_in_state` 两列（freq, jiffies）反过来验证哪些档真的被用过。debugfs 里若有 `cpu_cpufreq`/`msm_cpufreq`，里面的 `L2/L3` 表直接给 level 映射。
**大小**：约 20–60 KB。

## 五、真机也解决不了的

| 项 | 为什么 |
|---|---|
| **SSC 传感器服务端** | Android 的 SSC 是 QMI/SMD + `libsns_*_skel.so`（跑在 ADSP 上），Apple 侧对应物是 `SensorKit`/`IOHIDFamily` 私有服务，**协议与服务端都不存在**。97 个 zone 与 82 个 sensor 名拿到了也没法「跑起来」。 |
| **ADSP 上的 AudioReach / ICP / EVA 固件** | `adsp.b00..b25`（56 段）、`CAMERA_ICP.b00..b20`、`evass.*` 都是 **Hexagon ELF**。iOS 内核不能执行 Hexagon 指令，POSIX 侧也没有 FastRPC 对端。`Mi_acdb_cal.acdb` 44 MB 同理——只能在 Hexagon 的 APM 里加载。 |
| **X85 基带** | `modem.b08` 43 MB 固件 + `amss20.bin` 7.3 MB 要在 Hexagon + TZ 里跑。iOS 侧没有 MHI、没有 QRTR router、没有 TZ 授权路径。`pandora_modem.c` 头注释自己写的「Not done yet: … mcfg actually reaching the modem」本质不可达。 |
| **TZ 授权的 PAS**（ADSP/CDSP/modem/WPSS） | `auth_and_reset` 走 QSEE。iOS 侧没有 QSEE 等价物，也没有签名链。 |
| **AMFI / 信任链** | 与设备数据无关，是纯 iOS 侧问题（`STATUS-20261110` 已定位为 trust cache 少 7 条 cdhash）。 |
| **面板 DDIC 私有初始化命令** | `panels/*.xml` 里的 DSC/DDIC 序列有一部分是面板厂 spec 独有的私有命令，Android 侧也只经 `msm_drm` 下发、不落盘。 |
| **指纹匹配算法** | `fingerprint.goodix_us2.so` 52,168 B 是被 strip 的 ARM 用户态库，依赖 Android bionic + HIDL/AIDL HAL + `libmmfp.so`；us2 的模板与比对全在黑盒里。 |
| **PMIC efuse / XO 校准** | 一次性烧录，读得出但只在 QCOM 自家 XBL 里有语义。 |
| **`sweetfb_hz` 写死 60 / metal2vulkan 不复用 pipeline** | 这两个是**我们自己的代码问题**，不是缺数据。 |

## 六、建议的一次性采集脚本（P0 + P1，可直接贴给用户）

> 用法：手机连上、`adb devices` 能看到 `6f17201d` 之后，在 **Git-Bash**（先 `export MSYS_NO_PATHCONV=1`）里整段粘贴。
> 需要 root。产物落在当前目录 `popsicle-need-<日期>/`，总计约 40 MB。

```bash
export MSYS_NO_PATHCONV=1
S=6f17201d
O=popsicle-need-$(date +%Y%m%d-%H%M)
mkdir -p "$O" && cd "$O"

# ---------- 0. 前置检查 ----------
adb devices | grep -q "$S" || { echo "设备 $S 不在线，先插上再跑"; exit 1; }
adb -s $S shell "su -c id" | grep -q "uid=0" || { echo "没有 root，后面全废"; exit 1; }

# ---------- 1. 设备侧建目录 + 挂 debugfs ----------
adb -s $S shell "su -c 'mkdir -p /data/local/tmp/need && mount -t debugfs none /sys/kernel/debug 2>/dev/null; echo ok'"

# ---------- 2. [P0-1] regulator 运行时状态 ----------
adb -s $S shell "su -c 'cat /sys/kernel/debug/regulator/regulator_summary'"   > 10-regulator_summary.txt
adb -s $S shell "su -c 'cat /sys/kernel/debug/regulator/regulators'"          > 11-regulators.txt

# ---------- 3. [P0-2] 时钟树 ----------
adb -s $S shell "su -c 'cat /sys/kernel/debug/clk/clk_summary'"               > 12-clk_summary.txt

# ---------- 4. [P0-3] CPU 频率 + CPUCV ----------
adb -s $S shell "su -c 'for p in /sys/devices/system/cpu/cpufreq/policy*; do \
  echo \"== \$p\"; echo -n \"avail: \"; cat \$p/scaling_available_frequencies; \
  echo -n \"max/min: \"; cat \$p/cpuinfo_max_freq \$p/cpuinfo_min_freq; \
  echo \"-- time_in_state\"; cat \$p/stats/time_in_state; done'"                > 13-cpufreq.txt
adb -s $S shell "su -c 'ls /sys/kernel/debug/ | grep -iE \"cpu|cpufreq|cpuhv|epss|qcom\"; \
  cat /sys/kernel/debug/cpufreq/* 2>/dev/null'"                                > 13b-cpufreq-debugfs.txt

# ---------- 5. [P0-4] crus_calr ----------
adb -s $S shell "su -c 'ls -la /mnt/vendor/persist/audio/'"                   > 14-persist-audio-ls.txt
adb -s $S shell "su -c 'tar -C /mnt/vendor/persist -cf - audio'"              > 14-persist-audio.tar

# ---------- 6. [P0-5] 完整 dmesg + logcat ----------
adb -s $S shell "su -c 'dmesg'"                                               > 15-dmesg-full.txt
adb -s $S shell "su -c 'logcat -b all -d'"                                    > 16-logcat.txt

# ---------- 7. [P1] 触控两套 + 指纹 ----------
adb -s $S shell "su -c 'dmesg | grep -iE \"goodix|GTP-|syna|tcm\""'"          > 20-touch-dmesg.txt
adb -s $S shell "su -c 'ls -la /proc/touchpanel /sys/class/touch 2>/dev/null'" > 20b-touch-sysfs.txt
adb -s $S shell "su -c 'dmesg | grep -iE \"xiaomi-fp|mifp|qbt\""'"            > 22-fp-dmesg.txt
adb -s $S shell "su -c 'ls -la /dev/mifp_id /dev/qbt* /sys/class/fingerprint* 2>/dev/null'" > 22b-fp-dev.txt

# ---------- 8. [P1] 相机 OTP ----------
adb -s $S shell "su -c 'ls -laR /mnt/vendor/persist/camera /data/vendor/camera 2>/dev/null'" > 21-cam-ls.txt
adb -s $S shell "su -c 'tar -C /mnt/vendor/persist -cf - camera 2>/dev/null'"  > 21-cam-persist.tar
adb -s $S shell "dumpsys media.camera"                                        > 21b-dumpsys-camera.txt

# ---------- 9. [P1] BT / thermal / UFS / USB / modem / WiFi ----------
adb -s $S shell "su -c 'ls -laR /mnt/vendor/persist/bluetooth /data/vendor/bluetooth 2>/dev/null'" > 23-bt-ls.txt
adb -s $S shell "settings get secure bluetooth_address"                       >> 23-bt-ls.txt
adb -s $S shell "su -c 'for z in /sys/class/thermal/thermal_zone*; do echo \"== \$z \$(cat \$z/type)\"; \
  cat \$z/trip_point_*_temp \$z/trip_point_*_type 2>/dev/null; done'"          > 24-thermal.txt
adb -s $S shell "su -c 'ls /sys/bus/nvmem/devices/; for n in /sys/bus/nvmem/devices/*/nvmem; do \
  echo \"== \$n\"; od -An -tx1 -N64 \$n; done'"                                > 24b-nvmem.txt
adb -s $S shell "su -c 'cat /sys/block/sda/device/{model,rev,vendor} 2>/dev/null'" > 25-ufs.txt
adb -s $S shell "dumpsys usb"                                                 > 26-usb.txt
adb -s $S shell "su -c 'dmesg | grep -iE \"mpss|glink|qrtr|ipcrtr|subsys\""'"  > 27-modem.txt
adb -s $S shell "su -c 'ls -laR /vendor/firmware /mnt/vendor/persist/wlan 2>/dev/null'" > 28-wifi-fw.txt
adb -s $S shell "su -c 'dmesg | grep -iE \"cnss|wlan|pcie\""'"                > 28b-cnss.txt

# ---------- 10. 收尾：日志 + 校验 ----------
adb -s $S shell "su -c 'dmesg | tail -200'"                                   > 99-dmesg-tail.txt
sha256sum *.txt *.tar > 99-SHA256SUMS.txt 2>/dev/null
echo "=== 采完，产物在 $(pwd) ==="
ls -la
echo "=== 关键三项自检 ==="
grep -c "" 10-regulator_summary.txt 12-clk_summary.txt 13-cpufreq.txt 14-persist-audio-ls.txt 15-dmesg-full.txt
```

**跑完之后请把这 5 个文件先发回来**（其余可后补）：

1. `10-regulator_summary.txt`
2. `12-clk_summary.txt`
3. `13-cpufreq.txt`
4. `14-persist-audio.tar`（或 `14-persist-audio-ls.txt` 若目录为空）
5. `15-dmesg-full.txt`

—— 这 5 个覆盖了 P0 的全部 5 项，能一次性解掉 regulator / clock / cpufreq / 音频校准 / 各子系统初始化顺序，也就解掉了当前最卡的五处。
